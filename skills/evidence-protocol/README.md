# 任务证据协议（临时功能名）

一个约束 Agent “不要猜完成”的通用 Skill。

它从用户下任务的第一步就开始工作：先拆需求，把要求分成数据、代码、运行、视觉、交互、性能、仓库状态、主观质量等不同属性，再为每种属性指定正确的验证方式。

它解决的典型问题：

- 没看实际画面，只看坐标就说 UI 位置正确
- 没跑程序，只看代码就说功能已经修好
- 没查来源，就给出一个看起来合理的数据
- 单测通过，就说整个产品 100% 没问题
- GitHub 写入请求成功，就默认远端文件内容完全正确
- Agent 没能力判断主观体验，却替用户宣布验收通过

核心规则只有一句：

**任何“完成、正确、通过、已确认”，都必须有与该属性匹配的证据。**

## 怎么用

把 `SKILL.md` 放进支持 Skills 的 AI 工具中，并让它在开发、调试、数据查询、文件修改、UI 调整、自动化操作等需要验证结果的任务里加载。

这个 Skill 不要求 Agent 每次都输出一大张验收表。简单任务内部完成拆解即可，复杂任务或存在关键歧义时再显式展示验收条件。

## 它会做什么

接任务时：

1. 拆解用户要求
2. 判断每项要求属于什么属性
3. 判断是否存在会影响结果的歧义
4. 确定正确的验证方式
5. 判断自己有没有验证能力

执行中：

1. 边做边验证
2. 保存关键证据
3. 不把“应该可以”升级成“已经通过”

交付时：

1. 每个通过项给出证据
2. 不能验证的明确标记
3. 主观判断交给用户
4. 禁止无证据宣布 100% 完成

## 最常见的一条边界

代码、坐标、配置、类型检查都是静态证据。

它们不能自动证明：

- 真实运行正确
- 页面看起来正确
- 交互体验正确
- 数据当前仍然正确

证据必须和需要证明的属性匹配。

# 成书监控规则

每次碎片入库后自动检查所有书的完整度。

## 三个阈值

### 1. 章节素材充足（某章累计≥5条碎片）

动作：向 alert.md 写入「第X章已有5条碎片，内容充实，建议二审」

触发条件：碎片的 chapter 字段指向的章节累计碎片数 ≥ 5

### 2. 全书骨架成形（全书累计≥10条碎片）

动作：向 alert.md 写入「本书已有X条碎片，可以开始整理章节结构」

触发条件：书的 totalFragments ≥ 10

### 3. 书稿接近完成（完整度 ≥ 80%）

动作：
1. 向 alert.md 写入「书稿接近完成，建议进行可读性优化」
2. 自动生成全书大纲草案（列出所有章节和碎片数）
3. 自动检测缺失的章节类型（比如只有踩坑没有解法、只有事实没有实例）

触发条件：completeness ≥ 80

## 完整度计算

```
完整度 = 已有内容的章节数 / 总章节数 × 100%

已有内容 = 该章节碎片数 ≥ 3
总章节数 = 书刚创建时的预设章节

如果碎片中新增了预设之外的章节，总章节数重新计算。
```

## alert.md 格式

每次追加，不覆盖旧内容。格式：

```
## [YYYY-MM-DD] 完整度：当前值%

状态：XXX

触发阈值：[阈值名称]

建议操作：[具体动作]
```

## 草稿自动生成

当完整度≥80%时，遍历该书所有章节，按以下模板生成草稿：

```
# 章节名

## 知识点
（碎片的核心结论列表）

## 实例
（碎片中提取的具体例子，标注来源）

## 经验
（碎片中的教训和建议汇总）

## 待补充
（碎片中标记为「未验证」或缺失的内容）
```

草稿存为 chapters/章节名-草稿.md，不覆盖已有正文。

# 榨知机.skill · 把对话榨成素材

## 核心机制

每次对话结束后，自动扫描本轮全部内容，把你自己的结论性思考摘出来。不是你问了AI什么，是你在对话过程中形成的、属于你自己的思考成果。

摘出来后，AI先自检质量，达标才入库。不达标直接扔。

## 捕获什么

主要捕获你在对话中形成的五类思考成果：

| 类型 | 是什么 | 示例 |
|------|--------|------|
| 判断 | 你做出了选择或下了结论 | 比较了Cursor和OpenCode，Cursor上手快但长期用context window满了行为异常，OpenCode开源可控。结论：长期项目用OpenCode |
| 洞察 | 你想通了一个之前没明白的事 | 之前以为用户要更多功能，分析后台数据发现用户最常用的只有3个功能，他们真正要的是这3个功能稳定可预期。结论：堆功能不如保核心 |
| 决策 | 你决定怎么做 | 踩了两次AI改崩项目的坑之后决定：每次新任务前先让AI查Git状态，提交基线版本再开工 |
| 反思 | 你发现自己之前想错了 | 之前觉得AGENTS.md写完了就不用动了，实际跑下来发现只能管通用规则，不同项目需要单独的skill补充 |
| 提炼 | 你从信息中抽出了自己的理解 | 试了交叉审查法：同一个问题分别问两个模型，再综合。发现90%的情况下第二个模型能补第一个漏掉的关键点。提炼成固定工作流 |

## 条目格式（案例分析法）

每条记录不是笔记摘要，而是一个微型案例分析。必须包含完整的推理链条：

1. 现象/问题：遇到了什么情况、对比了什么数据、看到了什么差异
2. 分析：为什么会出现这个现象？背后是什么原理？多组数据对照说明了什么？
3. 结论：从这个分析中提炼出什么可执行的判断或方法

核心要求：别人读完这条记录，不仅知道你得出了什么结论，还能复现你的推理过程。

格式示例：

```
- 对比了同一批发布的几篇文章的数据。其中一篇用了信息缺口型标题（抛出一个让人好奇的问题），刚好蹭了当日热点，阅读量过万。另一篇教具体技能的内容完读率很高（45%），但阅读量只有几十。同样是一个人写的，内容质量也接近，唯一的变量是标题类型。这个对比说明：标题对点击率的影响比内容质量本身更大。原因是信息缺口型标题制造了一种认知缺口——读者心里有了一个未完成的问题，必须点开才能填补。蹭热点则让这个缺口有了时效性，不点开就过期了。结论：写标题时优先制造信息缺口，其次才考虑蹭热点；纯教程型标题即使内容再好点击率也天然偏低。
```

一条高质量记录 = 别人读完能复现你的推理过程，而不只是看到结论。

## 质量自检（AI必须过）

每一条在入库前，AI必须自检以下六项，全部通过才保存：

1. 这是用户自己的结论，不是复述AI的回答
2. 包含完整上下文（背景+过程+结论），不是一句没头没尾的话
3. 内容具体，有真实场景或案例支撑，不是空泛的感悟
4. 带有用户的判断或态度，不是中性的事实陈述
5. 用户三个月后回头看依然能看懂、觉得有用
6. 一个条目只讲一件事
7. 没有内部代号、项目编号、对话引用——任何外部读者都能直接看懂

一项不通过就舍弃。标准极高，宁少勿滥。

## 唯一露面的时候

你平时感觉不到它的存在。它只在你每次对话结束后出现，输出一句话：

提取了2条碎片，归到开发经验 → 技术决策

或者：

本轮未提取有价值的思考成果，跳过。

不啰嗦，不刷屏。你知道它工作了就行。除此以外它不主动说任何话。

## 查看素材

任何时候想看积累进度，说 看看我的榨知机 或 我的素材库：

```
📚 你的素材库

├── 技术决策（4条）
├── 协作方法（5条）
└── 安全与规范（3条）

写作方法论（10条）
├── 技巧体系（4条）
├── 标题与开头（3条）
└── 风格演变（3条）

产品思考（3条）
└── 产品与市场（3条）
```

想看某个主题详情，说 打开开发经验：

```
# 开发经验

## 技术决策

- 比较了Cursor和OpenCode做主力IDE。Cursor上手快但用了两周发现context window满了之后行为异常，对话长了开始编造代码。OpenCode初期配置麻烦但开源可控。结论：长期项目用OpenCode

- 分析小程序后台数据发现用户最常用的功能只有3个，其他十几个功能使用率不到5%。之前一直在堆新功能，但用户真正要的是核心功能稳定可预期。结论：停止加功能，集中精力打磨核心

## 协作方法

- 试了交叉审查法：同一个问题分别问两个模型再综合。发现90%的情况下第二个模型能补第一个漏掉的关键点，尤其是边界情况和异常处理。现在固定用这个工作流

- 修bug曾经和同一个AI来回扯了两小时。改成三步：先让AI只分析不修代码，再写最小复现用例确认问题，最后换模型重述问题。三步加起来20分钟
```

## 与上次对话的衔接

下次开新对话时，榨知机自动加载所有主题的素材册，让AI知道你的立场、判断和结论。不需要手动翻文件，不需要说帮我看看之前聊了什么。

## 三件事

第一件事是喂回给AI。下次新对话AI自动加载素材，知道你的立场和判断。

第二件事是分类归档。所有摘出来的碎片自动归类到对应主题的方向下。

第三件事是素材沉淀。同一主题的碎片自动累积到同一份文件中，方向越来越充实。

## 没有终点

没有完成概念。它一直跑，永远在收，永远在分。

## 如何使用

安装：把榨知机.skill 放到你的 skill 目录，告诉 AI 加载，首次指定 juice/ 目录位置。

日常：正常聊天。每次对话结束自动输出一句话摘要。

查看：说 看看我的榨知机 或 打开[主题名]。

## 用户职责

1. 首次使用时指定 juice/ 目录位置
2. 碎片级别无需任何操作

## 注意事项

- 不要编造用户没说过的话。只摘用户自己形成的结论
- 质量自检不过的碎片直接丢弃，不进文件
- 去重时宁可保留两条相似也不要错误合并
- 从不主动在对话中推任何内容，只在你问的时候展示

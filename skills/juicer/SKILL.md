# 榨知机.skill · 把思考榨成书

## 核心机制

每次对话结束后，自动扫描本轮全部内容，把你自己的结论性思考摘出来。不是你问了AI什么，是你在对话过程中形成的、属于你自己的思考成果。

不需要你说收一下，不需要任何触发词。每次跑完在对话中输出摘要，让你知道它做了什么。任何时候你可以问工作状态，它会汇报当前进度和所有输出位置。

## 捕获什么

主要捕获你在对话中形成的五类思考成果：

| 类型 | 是什么 | 示例 |
|------|--------|------|
| 判断 | 你做出了选择或下了结论 | A方案快但维护成本高，选B方案 |
| 洞察 | 你想通了一个之前没明白的事 | 用户要的不是功能多，是功能可预期 |
| 决策 | 你决定怎么做 | 以后都先plan再动手 |
| 反思 | 你发现自己之前想错了 | 之前觉得Electron好，现在看来太重了 |
| 提炼 | 你从信息中抽出了自己的理解 | AI协作的关键不是模型，是你的指令质量 |

没有以上信号就不产生碎片，跳过本轮。宁可漏也不要误收。

## 三个反馈机制

### 机制一：每次运行输出摘要

对话结束后，榨知机自动输出：

```
🧪 榨知机本轮捕获报告
提取了2条碎片
  1. 判断 A方案快但维护成本高，选B方案更稳
  2. 洞察 用户要的不是功能多，是功能可预期
归类到书 开发经验 → 章节 技术决策

碎片文件位置 juice/fragments/2026-07-30-判断-A方案快但维护成本高选B方案更稳.md
```

如果没有提取到有价值的碎片：

```
🧪 榨知机本轮未提取到有价值的思考成果，跳过。
```

### 机制四：整理命令

当收到阈值提醒后，说 整理我的书 或 整理[书名]。

榨知机会做三件事：

第一件事：扫描该书所有碎片，按主题聚合出章节建议

第二件事：输出建议的章节结构让你确认

```
📖 开发经验 章节结构建议

当前碎片 12条
建议分 3个章节

章节1 工具选型（4条）
  碎片 A方案比B方案维护成本低
  碎片 Electron太重了想切Tauri
  碎片 Cursor context window异常
  碎片 DeepSeek写脚本够用

章节2 协作方法（5条）
  碎片 交叉审查多个模型方案
  碎片 修bug三步法
  碎片 验收标准三问
  碎片 AI默认最短路径优先
  碎片 让AI自我批评代码

章节3 安全与规范（3条）
  碎片 没有Git就不要改项目
  碎片 增量修改约束边界
  碎片 AGENTS.md的维度

你觉得这个结构对吗？可以调整章节顺序、合并或拆分，确认后我生成章节草稿。
```

第三件事：你确认后，自动把碎片重排成章节草稿写入 books/书名/chapters/

### 机制二：状态命令

任何时候说 告诉我榨知机的工作状态 或 榨知机状态：

```
📊 榨知机运行状态
运行至今 7天
累计捕获 24条碎片
激活的书 3本（开发经验/产品思考/写作方法）
最后一次捕获 今天 14:32（提取了2条）
待分类碎片 0

碎片目录 juice/fragments/
每本书详情 juice/books/书名/alert.md
运行日志 juice/run-log.md
```

### 机制三：运行日志

在 juice/ 目录生成 run-log.md，每次运行追加一条记录：

```
## 2026-07-30 14:32
本轮提取 2条碎片
  1. 判断 A方案快但维护成本高，选B方案更稳
  2. 洞察 用户要的不是功能多，是功能可预期
归类 开发经验 → 技术决策
当前累计 24条碎片

## 2026-07-30 11:15
本轮未提取内容，跳过。
```

## 自动回喂机制

下次开新对话时，榨知机自动做两件事：

1. 根据对话上下文，从 juice/books/ 和 juice/fragments/ 中检索相关的历史记录
2. 在对话开始时加载到 AI 上下文中，让 AI 知道你之前的立场、判断和结论

你不需要手动翻文件，不需要说帮我看看之前聊了什么。AI 自己知道。

## 三件事

第一件事是喂回给AI。下次你开新对话，AI自动加载这些记录，知道你的立场是什么、你做过什么判断、你得出了什么结论。你不用把同样的思考过程重来一遍。

第二件事是帮你整理。所有摘出来的碎片自动分类、去重、归到对应主题下。你今天对技术选型做了判断，明天对产品方向做了分析，它们会进到同一本书的同一个章节里。

第三件事是自动出书。同一个主题积累到一定数量，它会自动重排成可读的章节草稿。累计10条提醒你整理结构，某个章节累计5条提醒内容充实，到80%完整度自动生成初稿。

## 输出目录

所有输出集中在 juice/ 目录：

```
juice/
├── run-log.md              每次运行的记录（自动追加）
├── fragments/              原始碎片按日期存
│   ├── YYYY-MM-DD-类型-核心摘要.md
│   └── ...
├── books/                  成体系的书
│   ├── 书名/
│   │   ├── book.json       元数据：完整度、章节列表、碎片数
│   │   ├── chapters/
│   │   │   ├── 01-章节名.md
│   │   │   └── ...
│   │   └── alert.md        阈值到达时写入
│   └── ...
└── inbox/                  待分类碎片（新主题未定义时放入）
    └── YYYY-MM-DD-类型-核心摘要.md
```

这个 juice/ 目录放在你的项目根目录或用户指定路径。首次安装时榨知机会告诉你它建在哪。

## 成书监控

每次碎片入库后重新计算完整度，检查三个阈值：

- 某本书累计10条碎片 → alert.md 写入：可以开始整理结构
- 某个章节累计5条碎片 → alert.md 写入：本章内容充实，建议二审
- 全书完整度 ≥ 80% → alert.md 写入：书稿接近完成，建议进行可读性优化

完整度 = 已有内容的章节数 / 总章节数。每个章节 ≥ 3 条碎片算初步完整。

## 书的三层质量

1. 知识层：碎片聚合成的章节正文，信息准确，有细节
2. 叙事层：书有自己的语言风格，不是碎片拼接。章节之间有过渡、有递进
3. 可读层：包含隐喻和实例。隐喻从碎片中的类比自然提取，不从外部编造

在首次达到80%完整度时触发一次重构，把所有碎片重排成可读的草稿。

## 如何使用

### 安装

1. 把榨知机.skill 放到你的 skill 目录
2. 告诉 AI 加载这个 skill
3. 首次加载时指定 juice/ 目录位置

### 日常使用

正常跟AI聊天。每次对话结束后榨知机自动运行并输出摘要。

想看工作状态，直接说 告诉我榨知机的工作状态 或 榨知机状态。

### 查看输出

- 看碎片：打开 juice/fragments/ 目录
- 查进度：看 juice/books/书名/alert.md
- 翻历史：看 juice/run-log.md
- 待分类：看 juice/inbox/

## 用户职责

1. 首次使用时指定 juice/ 目录位置
2. 收到 alert 后二审章节草稿，润色可读性
3. inbox/ 中有待分类碎片时定义新书
4. 碎片级别无需任何操作

## 注意事项

- 不要编造用户没说过的话。只摘用户自己形成的结论
- 去重时宁可保留两条相似碎片也不要错误合并
- 书没有达到阈值之前不在对话中主动提醒（但每次运行摘要和 run-log 仍然工作）
- 隐喻从碎片原文中已有的类比提取，不要创造

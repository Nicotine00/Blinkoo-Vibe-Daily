# 榨知机.skill · 把对话榨成素材

## 核心机制

每次对话结束后，自动扫描本轮全部内容，把你自己的结论性思考摘出来。不是你问了AI什么，是你在对话过程中形成的、属于你自己的思考成果。

摘出来后，AI先自检质量，达标才入库。不达标直接扔。

## 捕获什么

主要捕获你在对话中形成的五类思考成果：

| 类型 | 是什么 | 示例 |
|------|--------|------|
| 判断 | 你做出了选择或下了结论 | A方案快但维护成本高，选B方案 |
| 洞察 | 你想通了一个之前没明白的事 | 用户要的不是功能多，是功能可预期 |
| 决策 | 你决定怎么做 | 以后都先plan再动手 |
| 反思 | 你发现自己之前想错了 | 之前觉得Electron好，现在看来太重了 |
| 提炼 | 你从信息中抽出了自己的理解 | AI协作的关键不是模型，是你的指令质量 |

没有以上信号就不产生碎片，跳过本轮。宁可漏也不要误收。

## 质量自检（AI必须过）

每一条碎片在入库前，AI必须自检以下五项，全部通过才保存：

1. 这是用户自己的结论，不是复述AI的回答
2. 内容具体，有场景或细节支撑，不是空泛的感悟
3. 带有用户的判断或态度，不是中性的事实陈述
4. 用户今后回头看会觉得有用，不是一时兴起的废话
5. 能用一句话说清核心，不是散装的流水账

一项不通过就舍弃。标准极高，宁少勿滥。

碎片的质量比数量重要。10条高质量碎片能撑起一个章节，50条垃圾碎片什么用都没有。

## 只在两个时候露面

你平时感觉不到它的存在。它只在两个时候出现。

### 每次对话结束

输出一句话：

提取了2条碎片，归到开发经验 → 技术决策

或者：

本轮未提取有价值的思考成果，跳过。

不啰嗦，不刷屏。你知道它工作了就行。

### 同一主题累计10条碎片

自动输出素材编排建议：

```
📖 开发经验 素材编排建议

当前素材 12条，建议分3个方向

方向1 工具选型（4条）
  A方案比B方案维护成本低
  Electron太重了想切Tauri
  Cursor context window异常

方向2 协作方法（5条）
  交叉审查多个模型
  修bug三步法
  验收标准三问

方向3 安全与规范（3条）
  没有Git就不要改项目
  增量修改约束边界

素材已备好，可以动手写了。
```

不需要你说帮我整理一下。到了就推。

## 三件事

第一件事是喂回给AI。下次你开新对话，AI自动加载这些记录，知道你的立场是什么、你做过什么判断、你得出了什么结论。你不用把同样的思考过程重来一遍。

第二件事是分类入库。所有摘出来的碎片自动分类、去重、归到对应主题下。你今天对技术选型做了判断，明天对产品方向做了分析，它们会进到同一册素材里。

第三件事是备料。同一个主题积累到一定数量，它会自动汇总碎片、给出编排建议。10条提醒你可以开始写，某个子方向累计5条提醒这个角度够充实，到80%覆盖率建议动手。

你不写，它不写。它负责备料，你负责成文。

## 输出目录

所有输出集中在 juice/ 目录：

```
juice/
├── run-log.md              每次运行的记录（自动追加）
├── fragments/              原始碎片按日期存
│   ├── YYYY-MM-DD-类型-核心摘要.md
│   └── ...
├── books/                  素材册（按主题归档）
│   ├── 主题名/
│   │   ├── book.json       元数据：完整度、方向列表、碎片数
│   │   ├── directions/
│   │   │   ├── 01-方向名.md
│   │   │   └── ...
│   │   └── alert.md        阈值到达时写入
│   └── ...
└── inbox/                  待分类碎片（新主题未定义时放入）
    └── YYYY-MM-DD-类型-核心摘要.md
```

## 成册监控

每次碎片入库后重新计算，检查三个阈值：

- 同一主题累计10条碎片 → alert.md 写入：素材足够，可以开始写
- 某个子方向累计5条碎片 → alert.md 写入：这个角度素材充实
- 全主题覆盖面 ≥ 80% → alert.md 写入：素材基本齐备

覆盖度 = 已有素材的方向数 / 你预期的方向数。方向数由你首次使用该主题时设定。

## 素材质量要求

每一条入库的碎片必须达到：

1. 具体而非宽泛。不是要提升效率，是把plan步骤前置效率翻了一倍
2. 携带判断而非搬运。不是AI说可以这么做，是我试了之后发现可行
3. 可追溯而非孤立的。同样的判断在不同场景下出现时会互相关联

碎片达不到就不入库。标准是死的，没有商量空间。

## 如何使用

### 安装

1. 把榨知机.skill 放到你的 skill 目录
2. 告诉 AI 加载这个 skill
3. 首次加载时指定 juice/ 目录位置

### 日常使用

正常跟AI聊天。每次对话结束后榨知机自动运行并输出摘要。

### 查看输出

- 看碎片：打开 juice/fragments/ 目录
- 查进度：看 juice/books/主题名/alert.md
- 翻历史：看 juice/run-log.md
- 待分类：看 juice/inbox/

## 用户职责

1. 首次使用时指定 juice/ 目录位置
2. 各主题首次设置时告诉榨知机你期望的方向数（比如这本经验册你打算写几个方向）
3. 收到素材提醒后，从 juice/books/主题名/directions/ 取素材动手写
4. inbox/ 中有待分类碎片时定义新主题
5. 碎片级别无需任何操作

## 注意事项

- 不要编造用户没说过的话。只摘用户自己形成的结论
- 质量自检不过的碎片直接丢弃，不进inbox也不进fragment
- 去重时宁可保留两条相似碎片也不要错误合并
- 从不主动在对话中推整理建议以外的内容
- 你不动笔，它不会替你写。它的任务是备料

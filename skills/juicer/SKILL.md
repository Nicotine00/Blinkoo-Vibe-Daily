# 榨知机.skill · 把对话榨成书

## 核心机制

每次对话结束后，自动扫描本轮全部内容，找出值得记录的片段。不需要用户说收一下，不需要任何触发词。

但不再静默运行。每次跑完会在对话中输出摘要，让你知道它做了什么。任何时候你可以问榨知机的工作状态，它会汇报当前进度和所有输出位置。

## 三个反馈机制

### 机制一：每次运行输出摘要

对话结束后，榨知机自动输出：

```
🧪 榨知机本轮捕获报告
提取了2条碎片
  1. 技术选型 Electron vs Tauri 倾向 Tauri（理由：打包体积小）
  2. 踩坑 Cursor context window 满了之后行为异常
归类到书 开发经验 → 章节 工具选型

碎片文件位置 F:/skills/ juicer/juice/YYYY-MM-DD-HHmm-技术选型 Electron vs Tauri 倾向 Tauri.md
```

如果没有提取到有价值的碎片，输出：

```
🧪 榨知机本轮未提取到有价值的碎片，跳过。
```

### 机制二：状态命令

任何时候问榨知机的工作状态，输出：

```
📊 榨知机运行状态
运行至今 7天
累计捕获 24条碎片
激活的书 3本（开发经验/写作方法论/播客技巧）
最后一次捕获 今天 14:32（提取了2条）
待分类碎片 0

碎片目录 F:/projects/xxx/juice/fragments/
每本书详情 F:/projects/xxx/juice/books/书名/alert.md
运行日志 F:/projects/xxx/juice/run-log.md
```

触发方式：用户在对话中输入 告诉我榨知机的工作状态 或 榨知机状态 或 /status

### 机制三：运行日志

在输出根目录生成 run-log.md，每次运行追加一条记录：

```
## 2026-07-30 14:32
本轮提取 2条碎片
  1. 技术选型 Electron vs Tauri 倾向 Tauri
  2. 踩坑 Cursor context window 满了之后行为异常
归类 开发经验 → 工具选型
当前累计 24条碎片

## 2026-07-30 11:15
本轮未提取内容，跳过。
```

你可以随时打开这个文件看榨知机的完整工作记录。

## 输出目录

所有输出集中在一个根目录 juice/，方便查找和管理：

```
juice/
├── run-log.md              # 每次运行的记录（自动追加）
├── fragments/              # 原始碎片（自动产生）
│   ├── YYYY-MM-DD-HHmm-核心摘要.md
│   └── ...
├── books/                  # 成体系的书
│   ├── 书名/
│   │   ├── book.json       # 元数据：完整度、章节列表、碎片数
│   │   ├── chapters/
│   │   │   ├── 01-章节名.md
│   │   │   └── ...
│   │   └── alert.md        # 阈值到达时写入
│   └── ...
└── inbox/                  # 待分类碎片（新书未定义时放入）
    └── YYYY-MM-DD-HHmm-核心摘要.md
```

这个 juice/ 目录放在你的项目根目录或者用户指定的路径。首次安装时榨知机会告诉你它建在哪。

## 流程

### 第一步：自动捕获

对话结束后，扫描全部内容，识别以下信号：

| 类型 | 信号特征 | 示例 |
|------|---------|------|
| 决策 | 用户做了选择、下了判断 | 以后用XX方案 |
| 踩坑 | 遇到了问题、失败了 | XX方式行不通 |
| 规律 | 发现了重复出现的模式 | 每次做XX都会出这个错 |
| 评价 | 对工具/方法的态度 | XX比XX好用 |
| 灵感 | 可以后续深挖的点子 | 能不能做个XX |
| 事实 | 具体的参数、步骤、配置 | 端口是8080 |

没有以上信号就不产生碎片，跳过本轮。宁可漏也不要误收。

### 第二步：提炼

提取四要素：

1. 核心：用一句话说清楚这段内容在讲什么
2. 细节：具体的工具名、数据、操作步骤
3. 情绪：用户对这件事的态度（无语/惊喜/吐槽/无奈）
4. 结论：用户打算怎么做

信息不够的字段标未提及，不编造。

### 第三步：去重合并

检查已有碎片，按以下规则判定：

- 相同工具名 + 相同操作 = 重复。合并到已有碎片，补充新信息，不新建
- 相同观点 + 不同场景 = 不重复。旧碎片加交叉引用，新碎片独立保留
- 相同结论 + 不同角度 = 不重复。两条都保留，互加关联

去重结果写入碎片正文的 header，标记 merged-from 或 related-to。

### 第四步：归类入库

判断这个碎片属于哪本书的哪个章节。

如果已有分类匹配，直接归类到对应书和章节。
如果没有匹配的分类，放入 inbox/ 待分类区，输出摘要中提示用户新建书。

### 第五步：成书监控

每次碎片入库后重新计算完整度，检查三个阈值：

- 某本书累计10条碎片 → alert.md 写入：本书已有X条碎片，可以开始整理结构
- 某个章节累计5条碎片 → alert.md 写入：本章内容充实，建议二审
- 全书完整度 ≥ 80% → alert.md 写入：书稿接近完成，建议进行可读性优化

完整度计算公式：章节完整性 = 已有内容的章节数 / 总章节数。每个章节只要有 ≥ 3 条碎片就算初步完整。

## 书的结构

每本书有三层质量要求：

1. 知识层：碎片聚合成的原始章节正文，信息准确，有细节
2. 叙事层：书要有自己的语言风格，不是碎片的简单拼接。章节之间有过渡、有铺垫、有递进
3. 可读层：包含隐喻、实例。隐喻从碎片中的类比自然提取，不从外部编造

这三层在首次达到80%完整度时触发一次重构，把所有碎片重排成可读的草稿。

## 如何使用

### 安装

1. 把榨知机.skill 放到你的 skill 目录
2. 告诉 AI 加载这个 skill
3. 首次加载时指定 juice/ 目录的存放位置

### 日常使用

不需要任何操作。正常跟AI聊天，每次对话结束后榨知机自动运行。

如果想查看工作状态，直接说：

```
告诉我榨知机的工作状态
```

或者

```
榨知机状态
```

它就会汇报累计捕获情况、激活的书、输出位置。

### 查看输出

- 看碎片：打开 juice/fragments/ 目录
- 查进度：看 juice/books/书名/alert.md
- 翻历史：看 juice/run-log.md
- 待分类：看 juice/inbox/

### 管理知识库

- 收到 alert 后去 books/书名/chapters/ 审章节草稿
- 定义新书分类：在 juice/books/ 下新建文件夹和 book.json
- 多余的碎片手动删除或合并

## 用户职责

1. 首次使用时指定 juice/ 目录位置
2. 收到 alert 后二审章节草稿，润色可读性
3. inbox/ 中有待分类碎片时定义新书
4. 碎片级别无需任何操作

## 注意事项

- 不要编造用户没说过的话
- 去重时宁可保留两条相似碎片也不要错误合并
- 书没有达到阈值之前不在对话中主动提醒（但每次运行摘要和 run-log 仍然工作）
- 隐喻从碎片原文中已有的类比提取，不要创造

# 去重合并规则

新碎片入库前检查所有已有碎片。

## 判定矩阵

| 新碎片 vs 已有碎片 | 结论 | 操作 |
|---|---|---|
| 同样工具 + 同样的操作/结论 | 重复 | 合并到旧碎片下方，追加新信息，header加merged-from |
| 同样工具 + 不同的操作/结论 | 不重复 | 两条独立保留，互加related-to |
| 同样观点 + 不同的场景 | 不重复 | 两条独立保留，互加related-to |
| 同样结论 + 不同角度 | 关联 | 新碎片标 related-to 指向旧碎片 |
| 完全不同 | 独立 | 正常入库 |

## 合并示例

旧碎片：
```
工具：OpenCode
操作：对话中改了代码但没git commit
结论：每次改前先git status
```

新碎片：
```
工具：OpenCode
操作：改崩了才发现没提交
结论：改之前先git stash或commit
```

→ 合并成一条，在新碎片信息前标 [补充]，保留两条结论的时间线。

## 不能合并的情况

如果两条碎片语意相近但信息冲突（比如一条说X好用，一条说X不好用），不能合并。两条独立保留，互加 related-to。归到同一章节后，章节正文中自动生成观点对比段落。

# 瞭望台（Project Watchtower）

> 跨项目互通 skill：先登记项目清单，自动生成状态仓库与互通矩阵，让项目按规格、数据、情报三种方式互相供给。
> 兼容 opencode / Claude Code / WorkBuddy 等任何认 markdown 与全局指令的 AI 客户端。

## 它解决什么

同时推进多个项目时，项目之间互相失明：素材工具不知道下游要什么规格，同一产品的两个端数据各写各的，内容策划想看全项目动态要一个个会话打开问。瞭望台把每个项目变成广播台（状态文件）+ 一张互通地图（关联索引）+ 一段全局规则，项目之间开始互相看得见、互相喂得着。

它不是 AI 记忆工具，是项目分工协议。单项目用户用不上，多项目且项目间有供给关系时才值得搭。

## 安装（约 10 分钟，含登记）

### 第 1 步：交给 AI 一件事

把你的项目路径列表丢给 AI 就行（一行一个）。AI 会自己去读每个项目的目录搞清楚它是干嘛的，然后给你过目确认两样东西：项目名称（沟通口径）和一句话定位。接着 AI 会主动梳理项目间的互通点候选（谁产出谁消费、谁是同一产品多端、谁需要全局情报），你点头或否定，最后有异议就告诉 AI 你希望瞭望塔做什么。

顺带告诉 AI 状态目录（广播台）放哪，不指定就用默认建议（放所有项目之外的独立目录）。以后所有项目的状态文件都集中在这一个目录。

不用准备五条信息，用户只报路径、只做确认。

### 第 2 步：让 AI 生成整套

复制本 skill 给 AI 加载，它会自动产出：

```
project-states/
├── 关联索引.md              # 互通矩阵：谁该读谁、谁供给谁
├── _TEMPLATE.md             # 新建项目复用模板
├── README.md                # 机制说明 + 项目表
└── <项目名>-status.md        # 每项目一个对外广播台
```

### 第 3 步：写全局规则

在 AI 客户端全局指令文件（opencode 为 `~/.config/opencode/AGENTS.md`，Claude Code 为 `~/.claude/CLAUDE.md`）加入，并把首行换成你的状态目录绝对路径：

```markdown
状态目录 = <你的绝对路径，如 F:\project-states>
## 跨项目互通（强制）
1. 对话开始：列出状态目录下所有 *-status.md，先读关联索引，再逐文件读
2. 汇报：本项目与其他项目的互通边（本项目等着谁、谁等着本项目）、每个项目当前任务与最近进展
3. 每完成关键任务：更新本项目状态文件；成果涉及馈送其他项目，显式标注供给对象
4. 未进过的项目：写待该会话更新，不编造
```

状态目录放哪？跨盘符共享时放公共盘根目录（如 `F:\project-states\`），单机多项目可放用户目录。换位置只改全局规则一处。

### 第 4 步：接入每个项目

每项目复制 `_TEMPLATE.md` 为 `<项目名>-status.md` 填定位；项目根 AGENTS.md 追加一行：`每完成关键任务，更新 <状态目录>/<项目名>-status.md`。

## 日常使用

- **汇报**：说「瞭望台」或「看看其他项目进度」——AI 先讲当前项目的互通边（谁等我、我等谁、数据源漂移），再逐项目报进展 + 健康摘要
- **标记语义**：✦ 活跃（≤7 天）/ ⚪ 停滞（8-30 天）/ 🪦 失联（>30 天，建议退出）/ 🧩 占位（机制未激活，去项目里补一刀）
- **新项目**：登记五条信息，AI 自动接入互通网
- **规格变更**：写进进展并显式点名消费方，防止下游按旧规格干活

## 可选增强

- 互通矩阵按需加列：接口负责人、数据源位置、同步频率
- 多 AI 客户端共用时，把 skill 目录复制到各客户端 skills 路径，主源唯一

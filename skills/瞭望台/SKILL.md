# 瞭望台：跨 AI 会话的项目互通

一句话：AI 会话天生失忆，用一个状态仓库把「每个项目只活在自己对话里」补成「所有会话共享同一份最新动态」。

## 原理（30 秒理解）

- 每个项目一个 `<项目名>-status.md`，固定四段：当前任务 / 最近进展 / 阻塞 / 下一步
- 全局规则（AGENTS.md）让每个会话开工先扫仓库、干完写回仓库
- 本 skill 提供「查看 / 汇报 / 健康检查 / 接入新项目」的标准动作
- 文件即记忆：不建服务、不写代码、任何 AI 客户端都认 markdown

## 状态仓库约定

状态目录（下称 `<STATE_DIR>`）默认由全局 AGENTS.md 声明（本环境为 `F:\project-states\`）。换位置只改全局规则一处，skill 流程不变。

| 文件 | 用途 |
|---|---|
| `<项目名>-status.md` | 每项目一个，唯一状态文件 |
| `README.md` | 机制说明与项目表 |
| `_TEMPLATE.md` | 新建项目复制用模板 |
| `关联索引.md` | 可选：项目间「谁该读谁」矩阵 |

## 一、查看与汇报（用户要进度时）

1. 读 `<STATE_DIR>` 下所有 `*-status.md`，**跳过** README / `_TEMPLATE` / 索引 / 台账 / 脚本等系统文件
2. 若存在 `关联索引.md`：先读它，按矩阵确定当前项目该重点关注谁的动态，汇报时点一句
3. 每个项目按此格式汇报（3 行内）：

```
[状态标记] 项目名（上次更新 MM-DD）
  当前任务：一句话（完成度）
  进展/阻塞：最新 1-2 条
```

4. 状态标记规则（依据文件 LastWriteTime）：
   - ✦ 活跃：≤7 天有更新
   - ⚪ 停滞：8-30 天未更新
   - 🪦 失联：>30 天未更新（建议与用户确认是否退出项目表）
   - 🧩 占位：内容含「待该会话更新」（机制未被该项目会话激活）
5. 结尾给一行健康摘要：`N 个项目：X 活跃 / Y 停滞 / Z 占位`

## 二、新建项目接入

1. 复制 `_TEMPLATE.md` → `<项目名>-status.md`，填入一句话定位
2. 在项目根目录 AGENTS.md（或 CLAUDE.md）末尾追加一行：

   `每完成关键任务，更新 <STATE_DIR>/<项目名>-status.md`

3. 告诉用户：该项目下次会话会自动开始维护此文件

## 三、更新当前项目状态

- 完成关键任务后：最近进展追加一条 `yyyy-MM-dd：做了什么（结果一句话）`
- 保留最近 3-5 条，旧条目删掉，文件保持短小
- 同步刷新「当前任务」完成度
- 不写密钥、不写隐私

## 四、健康检查（维护者视角）

- 按 `*.status` 文件 LastWriteTime 算活跃度，见状态标记规则
- 占位文件：提示用户「去那个项目会话确认一次」，**不代写内容**
- 失联项目：建议从 README 项目表摘除或与大项目合并

## 五、避坑守则（每条都是真踩过的坑）

1. **不编造**：状态文件只写真实完成的事；没去过的项目写「待该会话更新」，不许猜
2. **单真相源**：跨系统部署副本一律从主源同步（见维护清单），禁止在副本上直接改
3. **命名对齐**：状态文件名用项目全名，不用目录缩写（例：目录 `F:\游戏素材制作工具`，项目名「像素素材制作工具」）
4. **汇报只读状态文件**：台账、地图、脚本等系统文件不进汇报上下文
5. **双轨必冲突**：项目内部已有自己的记忆/日志系统时，状态仓库是「唯一对外口径」，内部记录仅作运行日志

## 六、背景与动机（为什么这么建）

- 2026-08-13 起因：同时维护 6 个项目（公众号 / 像素游戏 / 素材工具 / 播客 / 两个小程序），会话互相失忆——公众号这边想拿游戏项目的进展当选题素材，只能重启那个项目挨个问
- 解法：一个目录 + 一份全局规则 + 一个 skill，让每个 AI 会话「自带值班表」
- 08-14 意外验证：另一个 AI 系统（WorkBuddy）自动遵守了这套约定，并自行衍生出关联索引 / 台账 / 工作区地图——约定一旦标准化，任何 agent 都能接入
- 教训：给 AI 定规则，最靠得住的载体不是聊天记录，是它每次开工必读的文件

## 维护清单（改了本 skill 之后）

- 同步部署副本：运行 `python F:/project-states/_install_skills.py`（或手动把 SKILL.md 覆盖到每个部署目录）
- 改完内容后确认 README.md 与 SKILL.md 仍一致

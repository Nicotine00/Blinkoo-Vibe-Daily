## 当前内容

### 📄 [AGENTS.md v2.0](AGENTS.md) — 新项目开工规则

在原有 Vibe Coding 协作规则上升级，新增**项目文件分类、依赖安装、GitHub 提交前检查、换电脑重建环境和发布包边界**。保留原版的开发规划、工作方式、测试和安全要求。

**怎么用**

1. 新项目开始前，将 [AGENTS.md](AGENTS.md) 放到**新项目的根目录**（若已有 AGENTS.md，先让 Agent 比较规则并合并，不能直接覆盖）。
2. 告诉 Codex / Claude Code / Cursor：**先读取 AGENTS.md，检查现有技术栈，再配置对应的开发环境和文件管理规则；给我方案确认后再改。**
3. 日常开发继续保留该文件，发生重大项目调整时同步维护。

提醒：AGENTS.md 是给 AI 看的**长期规则**，不是自动清理工具。依赖文件怎么排除、部署文件能不能忽略，需要 Agent 按真实项目判断。

### 🩺 [PROJECT-AUDIT.md](PROJECT-AUDIT.md) — 老项目体检与安全整理

项目已经做了一段时间，文件夹突然冒出几万个文件？不知道该备份哪些、GitHub 要同步哪些、开发手册和最终发布包应该怎么分？

**怎么用**

1. 在 **当前需要体检的项目** 中打开 Codex 或其他能读取本地文件的 Agent。
2. 打开 [PROJECT-AUDIT.md](PROJECT-AUDIT.md)，把“**复制给 Agent**”整段发给它（也可把文件交给 Agent 读取并要求执行体检）。
3. **第一轮只获取报告，不清理**。重点看“项目源码 / 本地依赖 / 正式素材 / 开发文档 / 构建发布文件 / 机密”各放在哪里。
4. 审核报告、做好项目外部备份，再单独批准具体修复。最后核实构建、运行与 GitHub 状态。

开发文档（如 AGENTS.md、开发手册、设计说明）通常值得留在 Git 中，但不一定属于交给最终用户的发布包。不要因为它们不参与运行就直接删除。

**两份文件搭配**：先用 PROJECT-AUDIT.md 诊断老项目，再把适合该项目的 AGENTS.md 2.0 长期规则补进去。

### 🍋 skills/juicer（榨知机）— 把对话榨成素材

自动捕获对话中你形成的结论性思考，精炼去重后按主题汇编成册。每次对话结束后自动扫描本轮内容，把你自己的判断、洞察、决策、反思、提炼摘出来，AI 自检质量达标后归档。下次新对话自动加载，AI 一开始就知道你的立场和结论。

**适合**

- 在对话中形成了自己的结论/决策/洞察，想积累个人知识资产但没记录习惯
- 长期用 AI 协作（写代码/写作/研究），想沉淀自己的方法论体系

**不适合**

- 记录 AI 给出的答案（那是笔记，不是素材）
- 需要全文对话存档

**怎么触发**

```
榨汁 / 榨知机 / 榨一下
我的素材库 / 看看我的榨知机
打开[主题名]  （如：打开开发经验）
```

对话结束时自动执行，不需要手动触发。

### 🎯 skills/wechat-title — 公众号爆款标题生成

基于 22 个「篇篇10W+」头部公众号的真实标题样本提炼的标题方法论 Skill。先判断内容所属领域（AI科技/商业/财经/成长职场/文化读书/健康/人物 7 大领域），再套用该领域头部账号的标题经验与模板库生成候选，最后过 10 条自检清单过滤。每条方法论都有真实样本例句背书。

**适合**

- 给公众号文章起标题（7 大领域全覆盖）
- 标题共创 / 多候选 A/B 测试
- 已有标题的优化与备选

**不适合**

- 长文写作（那是 khazix-writer 的活）
- 小红书/推特等短内容平台标题

**怎么触发**

```
帮我的文章起几个标题
这篇文章用爆文风格起标题
帮我优化这个标题
给标题出 10 个 A/B 候选
```

### 🗼 skills/瞭望台 — 跨 AI 会话的项目互通

同时开多个 AI 项目时，每个会话只活一次对话、互相失忆。瞭望台用一个状态仓库（每项目一个 `<项目名>-status.md`）+ 一份全局规则 + 一个 skill，让所有会话共享同一份最新动态：开工先扫仓库汇报进度、干完写回仓库、健康检查自动标出停滞/占位的死项目。零代码、零服务，任何认 markdown 的 AI 客户端都能用。

**适合**

- 同时维护 3 个以上 AI 项目，想一眼看到全局进度
- 一个项目要拿另一个项目的进展当素材（如公众号写游戏项目）
- 想给所有项目配一套「AI 值班表」，不依赖任何特定平台

**不适合**

- 只跑一个项目，没有跨会话互通需求
- 需要实时同步代码/文件本身（那是版本管理的事，不是进度）

**怎么触发**

```
瞭望台 / 看看其他项目进度 / 项目同步
各项目状态 / 互通 / 别的项目怎么样了
```

日常也有强制动作：每个会话开工自动读仓库、干完自动写回。

### 🧭 skills/restraint-skill — 让 Agent 只说证据能证明的话

克制不是语气保守。这个 Skill 从接任务时就先逐项覆盖用户原始要求、识别规则空白和隐含假设，再规划验收方式。复杂任务开工前先把“任务理解 + 验收计划”给用户看。执行时边做边留证，交付时逐项对回最初要求。没看画面就不能说视觉正确，没跑功能就不能说功能正常，没查来源就不能确认数据，用户没定义的奖励数值、时间阈值、权限和业务规则也不能自己猜。

**适合**

- Codex / Claude Code / Cursor 等 Agent 开发任务
- 数据查询、文件修改、GitHub 同步、UI 调整、功能验收
- 想阻止 Agent “猜完成”或只用谨慎措辞表演克制的场景

**核心规则**

```
原始需求 → 逐项覆盖 → 识别假设/规则空白 → 开工前规划证据 → 执行并留证 → 逐项验收
```

任何“完成 / 通过 / 正确 / 已确认”，都要回答：实际验证了什么，结果是什么，这份证据能证明到哪一步。

→ [SKILL.md](skills/restraint-skill/SKILL.md) · [README](skills/restraint-skill/README.md)
